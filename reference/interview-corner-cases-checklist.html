Technical Interview Corner Cases & Edge Cases Checklist

A battle-tested pre-flight verification checklist for high-stakes technical coding interviews, derived directly from Tech Interview Handbook standards.

1. Universal Pre-Flight Verification Protocol

Before Writing Any Code, Clarify With Your Interviewer:

  • Input Cardinality: Can the input be null, None, empty ([] or ""), or contain only 1 element?
  • Value Ranges: Are numbers strictly positive, or can they be zero or negative? Can intermediate calculations overflow 32-bit signed integers ($2^{31}-1$)?
  • Duplicates: Can the sequence contain duplicate values? Does the problem require returning unique combinations or all permutations?
  • Ordering: Is the input guaranteed to be sorted? Can we mutate the input array in-place, or is it read-only?
  • Memory Constraints: Is an $O(N)$ auxiliary hash map acceptable, or is $O(1)$ in-place space strictly required?

3. The 60-Second Final Code Walkthrough

Before Saying "I'm Done":

  1. Dry-run an edge case: Walk through your code with an empty input ([]) or single element ([1]). Did it crash with an IndexOutOfBounds or NullPointerException?
  2. Check loop bounds: Are indices 0-indexed or 1-indexed? Does the loop terminate or can it run infinitely?
  3. Confirm Return Type: Does the problem ask for the value, the index, the length, or a boolean?
  4. State Complexity: Confidently state time and auxiliary space complexity in Big-O, differentiating between heap memory and recursion stack frames.
