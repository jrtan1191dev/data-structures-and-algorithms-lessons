Big-O & Algorithmic Complexity Cheatsheet

Quick reference guide for asymptotic analysis, operational rules, and memory scaling.

1. The Growth Hierarchy

Big-O measures how time or space requirements grow as the input size n approaches infinity. Always aim for the lowest feasible tier:

Notation Name Typical Operations Input Size Tolerance (10⁷ ops/sec)
O(1) Constant Array index lookup, Hash map get/set, Math calculation Virtually unlimited (10⁹+)
O(log n) Logarithmic Binary Search, Balanced BST search Extremely large (10⁸+)
O(n) Linear Single loop, Array scan, String traversal n ≤ 10⁷
O(n log n) Linearithmic Merge Sort, Quick Sort (avg), Heap operations on n items n ≤ 10⁶
O(n²) Quadratic Nested loops over input, Bubble sort, Compare all pairs n ≤ 1,000 … 5,000
O(2ⁿ) Exponential Recursive subsets, brute-force search without memoization n ≤ 20 … 25
O(n!) Factorial Generating all permutations, brute force Traveling Salesperson n ≤ 10 … 12

2. Golden Simplification Rules

  • Rule 1: Drop Constants. O(2n + 5) → O(n). At scale, the slope factor doesn't alter the asymptotic curve.
  • Rule 2: Drop Non-Dominant Terms. O(n² + 100n + 5000) → O(n²). The highest-order power dwarfs everything else as n → ∞.
  • Rule 3: Separate Inputs Use Separate Variables. Traversing array A then array B is O(|A| + |B|), not O(2n). Nested iteration is O(|A| × |B|).
  • Rule 4: Multi-Step Algorithms Add or Multiply:
    • Sequential steps: Add complexities: O(A + B).
    • Nested operations (doing work inside a loop): Multiply complexities: O(A × B).

3. Time vs. Space: Two Memory Categories

  • Auxiliary Heap Space: Memory explicitly allocated for data structures (e.g. new HashSet(), list.append()).
  • Call Stack Space: Memory consumed by recursive function calls. Maximum recursion depth directly dictates call stack space:
    • Balanced Divide & Conquer (e.g. binary search, merge sort): log₂ n frames → O(log n) space.
    • Unbalanced or linear recursion (e.g. traversing linked list recursively): n frames → O(n) space.

4. Fundamental Structure Complexities

Data Structure Access Search Insertion Deletion Space
Array (Contiguous) O(1) O(n) O(n) (shift) O(n) (shift) O(n)
Dynamic Array (Append) O(1) O(n) O(1)* (amortized) O(1) (at end) O(n)
Hash Map / Hash Table N/A O(1) avg O(1) avg O(1) avg O(n)
Singly Linked List O(n) O(n) O(1) (at head) O(1) (given node) O(n)

*Amortized insertion in dynamic arrays accounts for occasional resizing and copying (O(n)) distributed across many O(1) appends.

5. Multi-Language Idiom Crosswalk

# Python Primitives & Dynamic Structures
# List (Dynamic Array): O(1) index, O(1) amortized append, O(n) insert/delete inside
arr = [1, 2, 3]
arr.append(4)         # O(1)
first = arr[0]        # O(1)

# Dict (Hash Map) & Set (Hash Set): O(1) avg lookup / insert
lookup = {"a": 1, "b": 2}
if "a" in lookup:     # O(1) average
    print(lookup["a"])
// TypeScript Primitives & Dynamic Structures
// Array (Dynamic): O(1) index, O(1) push, O(n) unshift/splice
const arr: number[] = [1, 2, 3];
arr.push(4);          // O(1)
const first = arr[0]; // O(1)

// Map & Set: O(1) avg lookup / insert
const lookup = new Map<string, number>();
lookup.set("a", 1);   // O(1)
if (lookup.has("a")) { // O(1)
    console.log(lookup.get("a"));
}
// Java Primitives & Collections
// ArrayList (Dynamic Array): O(1) get, O(1) amortized add, O(n) remove/add at index
import java.util.ArrayList;
import java.util.HashMap;

ArrayList<Integer> arr = new ArrayList<>();
arr.add(1);           // O(1) amortized
int first = arr.get(0); // O(1)

// HashMap: O(1) avg get/put
HashMap<String, Integer> lookup = new HashMap<>();
lookup.put("a", 1);   // O(1)
if (lookup.containsKey("a")) { // O(1)
    System.out.println(lookup.get("a"));
}
