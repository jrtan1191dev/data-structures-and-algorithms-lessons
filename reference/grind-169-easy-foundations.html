Grind 169: Core "Easy" Foundations Roadmap

Mastering the 41 canonical LeetCode Easy problems from the Tech Interview Handbook (26-Week Track). Organized module by module so you master foundational data structure invariants before escalating to Mediums.

🎯 Pedagogical Strategy: Why Master "Easy" Archetypes First?

In the Tech Interview Handbook 26-Week schedule, all 41 Easy problems are concentrated in Weeks 1 through 6. This front-loading is deliberate: every LeetCode Medium problem is simply an Easy concept combined with an extra constraint or edge condition, and every Hard is two Mediums stitched together.

By practicing the 41 Easy archetypes across all 13 core modules first, you build instantaneous fluency strength (syntax, boilerplate, boundary checks) and deep storage strength (mental models like Spatial Complement, LIFO Stacks, Fast/Slow Pointers, and Tree Invariants) before tackling multi-phase problem transitions.

1. The 5 Core Invariants of the "Easy" Curriculum

Before touching code, verify that you can articulate these 5 fundamental mental models from first principles:

1. Spatial Complement

Archetype: LC #1 Two Sum, LC #217 Contains Duplicate

Instead of comparing all pairs in $O(N^2)$, store traversed elements in a hash set/map and ask: Does $(target - x)$ already exist? Trades $O(N)$ RAM for instantaneous $O(1)$ pair discovery.

2. Converging Boundaries

Archetype: LC #125 Valid Palindrome, LC #977 Squares of a Sorted Array

Move two pointer indices toward each other from extremes. Monotonically narrows the candidate window in strict $O(N)$ linear time without allocating auxiliary copy buffers.

3. Pointer Speed Differentials

Archetype: LC #141 Linked List Cycle, LC #876 Middle of the Linked List

Advance slow by 1 hop and fast by 2 hops. Solves cycle detection and middle-node identification in $O(1)$ auxiliary memory by exploiting Floyd's relative speed ($\Delta v = 1$).

4. LIFO State Pairing

Archetype: LC #20 Valid Parentheses, LC #844 Backspace Compare

Push opening symbols onto an explicit execution stack. When an opener meets its expected closer, pop. An empty stack at the end guarantees well-formed nested structures.

5. Post-Order Tree Aggregation

Archetype: LC #104 Max Depth, LC #110 Balanced Tree, LC #543 Diameter

Let subtrees compute their height/depth first ($O(N)$ bottom-up DFS). Parent nodes aggregate child results and validate balance conditions without repeated re-traversals.

3. Diagnostic Litmus Test: The Easy Foundations

Test your understanding of the foundational invariants before moving on to Mediums:

🧠 Knowledge Check 1: Space Invariants
Memory Hierarchy
Why is Floyd's Tortoise and Hare algorithm preferred over a HashSet lookup in production systems when detecting a linked list cycle?
It runs in O(log N) runtime compared to linear time
It achieves O(1) auxiliary space without allocating heap node set references
It modifies the node pointer values to store visited markers in-place
It automatically sorts the nodes by address value to guarantee termination
🧠 Knowledge Check 2: Asymptotic Trade-offs
Time Complexity
In LC #1 (Two Sum), why is sorting the array and running two converging pointers suboptimal compared to a single-pass HashMap?
Two pointers cannot find negative complement values
Sorting mutates node pointers and triggers memory leaks
Sorting incurs an O(N log N) bottleneck and loses original index positions
Two pointers require an auxiliary priority queue of size K
