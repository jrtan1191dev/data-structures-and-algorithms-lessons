The Full Complexity Spectrum & Space Analysis

Demystifying O(log n), O(n log n), O(2ⁿ), and how space complexity actually behaves in physical RAM.

In Lesson 0001, we explored the baseline contrast between constant O(1), linear O(n), and quadratic O(n²). However, the vast majority of optimized interview solutions and high-performance algorithms live in the spaces between: specifically O(log n) and O(n log n), or when exploring exhaustive combinatorial choices, O(2ⁿ) and O(n!).

💡

The Logarithm Intuition

In computer science, log n almost always means log₂ n (base 2). Ask yourself: "How many times can I divide n in half before reaching 1?"
If n = 16: 16 → 8 → 4 → 2 → 1 → 4 steps (log₂ 16 = 4).
If n = 1,000,000: log₂(1,000,000) ≈ 20 steps!
An O(log n) algorithm transforms a million operations into twenty.

1. The Complete Time Spectrum Compared

Complexity Mechanical Meaning Common Encounters Operations for n = 1,000,000
O(1) Direct lookup without iterating Array index, Hash map get 1 operation
O(log n) Halving the search space each step Binary Search, BST lookup ~20 operations
O(n) Touching every element once Single loop, linear scan 1,000,000 operations
O(n log n) log n levels of work, each doing n steps Merge Sort, Quick Sort, Timsort ~20,000,000 operations
O(n²) Nested loops over input Comparing all pairs, Bubble sort 1,000,000,000,000 (Timeout!)
O(2ⁿ) Two recursive branches at every step All subsets, power set, brute recursion Exceeds atoms in universe for n > 300
O(n!) Every permutation of elements Traveling Salesperson (brute force) Uncomputable for n ≥ 15

2. What is O(n log n)? (Divide & Conquer)

Why do standard production sorting algorithms (Merge Sort, Python's Timsort, Java's Dual-Pivot Quicksort, JavaScript's V8 Timsort) take O(n log n) time?

Imagine taking an array of n items:

  1. You divide it in half repeatedly until each sub-array has length 1. How deep is this tree of divisions? log n levels deep.
  2. At each level of the tree, you merge the split pieces back together. Across all segments on any given level, you process exactly n total elements.
  3. Total operations = (Work per level) × (Number of levels) = n × log n = O(n log n).

3. Space Complexity: What Counts?

Beginners frequently misunderstand space complexity. Space complexity is not just new variables or arrays you allocate. It consists of two distinct components:

  • 1. Auxiliary Heap Space: New arrays, HashSets, HashMaps, or objects you explicitly construct.
  • 2. Call Stack Space (Recursion): Every time a function calls itself, the computer allocates a stack frame to remember local variables and return addresses. Deep recursion requires memory proportional to the maximum call stack depth.
🔍

Iterative vs. Recursive Space Contrast

Iterative Binary Search: Runs in O(log n) time and requires O(1) space (only two pointers: left and right).
Recursive Binary Search: Runs in O(log n) time, but consumes O(log n) auxiliary space on the call stack due to log n recursive frames.

4. Multi-Language Demonstrations

Example A: O(log n) Time, O(1) Space — Iterative Binary Search

# Time: O(log n) -> cuts search interval in half every loop
# Space: O(1) -> only uses two integer pointers
def binary_search(nums: list[int], target: int) -> int:
    left, right = 0, len(nums) - 1
    while left <= right:
        mid = left + (right - left) // 2
        if nums[mid] == target:
            return mid
        elif nums[mid] < target:
            left = mid + 1      # Discard left half
        else:
            right = mid - 1     # Discard right half
    return -1
// Time: O(log n) -> search range halved each step
// Space: O(1) -> no heap allocation, no recursion stack
function binarySearch(nums: number[], target: number): number {
    let left = 0;
    let right = nums.length - 1;
    while (left <= right) {
        const mid = Math.floor(left + (right - left) / 2);
        if (nums[mid] === target) {
            return mid;
        } else if (nums[mid] < target) {
            left = mid + 1;     // Discard left half
        } else {
            right = mid - 1;    // Discard right half
        }
    }
    return -1;
}
// Time: O(log n) -> halves search space on each iteration
// Space: O(1) -> constant auxiliary primitive variables
public class Search {
    public static int binarySearch(int[] nums, int target) {
        int left = 0;
        int right = nums.length - 1;
        while (left <= right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] == target) {
                return mid;
            } else if (nums[mid] < target) {
                left = mid + 1;     // Discard left half
            } else {

            }
        }

    }
}

Example B: O(n log n) Time, O(n) Space — Merge Sort Anatomy

# Time: O(n log n) -> log(n) split levels * O(n) merge work per level
# Space: O(n) -> temporary arrays allocated during merge
def merge_sort(nums: list[int]) -> list[int]:
    if len(nums) <= 1:
        return nums
    
    mid = len(nums) // 2
    left = merge_sort(nums[:mid])    # Recurse on left half
    right = merge_sort(nums[mid:])   # Recurse on right half
    
    # Merge step: O(n) time, O(n) temporary space
    merged = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            merged.append(left[i]); i += 1
        else:
            merged.append(right[j]); j += 1
    merged.extend(left[i:])
    merged.extend(right[j:])
    return merged
// Time: O(n log n) -> log(n) tree depth, O(n) work per level
// Space: O(n) -> requires auxiliary buffer to merge sub-arrays
function mergeSort(nums: number[]): number[] {
    if (nums.length <= 1) return nums;

    const mid = Math.floor(nums.length / 2);
    const left = mergeSort(nums.slice(0, mid));
    const right = mergeSort(nums.slice(mid));

    const merged: number[] = [];
    let i = 0, j = 0;
    while (i < left.length && j < right.length) {
        if (left[i] <= right[j]) {
            merged.push(left[i++]);
        } else {
            merged.push(right[j++]);
        }
    }
    return merged.concat(left.slice(i)).concat(right.slice(j));
}
// Time: O(n log n)
// Space: O(n) -> auxiliary temp array needed for merging
public class MergeSort {
    public static void sort(int[] arr, int l, int r) {
        if (l >= r) return;
        int m = l + (r - l) / 2;
        sort(arr, l, m);
        sort(arr, m + 1, r);
        merge(arr, l, m, r); // O(n) work copying to temp array
    }

    private static void merge(int[] arr, int l, int m, int r) {
        int[] temp = new int[r - l + 1]; // O(n) auxiliary space
        int i = l, j = m + 1, k = 0;
        while (i <= m && j <= r) {
            if (arr[i] <= arr[j]) temp[k++] = arr[i++];
            else temp[k++] = arr[j++];
        }
        while (i <= m) temp[k++] = arr[i++];
        while (j <= r) temp[k++] = arr[j++];
        System.arraycopy(temp, 0, arr, l, temp.length);
    }
}
