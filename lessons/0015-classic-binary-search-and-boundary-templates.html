Donald Knuth famously remarked: "Although the basic idea of binary search is comparatively straightforward, the details can be surprisingly tricky." It is a staple of technical interviews because boundary errors (off-by-one loops, infinite while loops) quickly reveal imprecise algorithmic reasoning.

💡

Tied to Your Interview Mission

Whenever an array is sorted or partially sorted, an interviewer expects an O(log n) solution. A linear O(n) scan will be immediately rejected. For $n = 1,000,000,000$, binary search terminates in just 30 comparisons!

1. The Power of Logarithmic Halving

Binary search compares the target against the middle element nums[mid]. Because the sequence is monotonic:

  • If nums[mid] == target: Target found in O(1).
  • If nums[mid] < target: The target cannot possibly reside in the left half. Discard [left ... mid] → left = mid + 1.
  • If nums[mid] > target: The target cannot reside in the right half. Discard [mid ... right] → right = mid - 1.

At each comparison, exactly half of the remaining search candidates are discarded: $\frac{n}{2}, \frac{n}{4}, \dots, 1 \implies \mathbf{O(\log n)}$ total steps.

Key Learning Point: Compare nums[mid] against nums[right]. If nums[mid] > nums[right], the pivot inflection point lies strictly in the right half (left = mid + 1). Otherwise, the minimum lies at or to the left of mid (right = mid).

3. The Classic Midpoint Overflow Bug

In Java, C++, and languages with fixed 32-bit signed integers, calculating midpoint as: 

int mid = (left + right) / 2; // BUG!

fails when left + right > 2,147,483,647. The sum overflows into a negative number, triggering an ArrayIndexOutOfBoundsException.

The Universal Safe Recipe: 

int mid = left + (right - left) / 2;

Because right - left can never exceed array capacity, overflow is mathematically impossible.

4. Rotated Sorted Array: Identifying the Monotonic Half

Array: [4, 5, 6, 7, 0, 1, 2], Target = 0
left = 0 (4), mid = 3 (7), right = 6 (2)

Check Left Half: nums[left] <= nums[mid] (4 <= 7) -> TRUE! Left half is normally sorted!
Is Target (0) in range [4, 7)? No.
Therefore, target MUST be in right half! -> left = mid + 1

5. Multi-Language Implementations: Search in Rotated Sorted Array

Solving LeetCode 33 (Grind 75) in $O(\log n)$ time and $O(1)$ space across Python, TypeScript, and Java: 

def search_rotated(nums: list[int], target: int) -> int:
    """
    LeetCode 33 (Grind 75) - Rotated Binary Search.
    Time Complexity:  O(log n) - halves search space each iteration.
    Space Complexity: O(1) - boundary pointers only.
    """
    left = 0
    right = len(nums) - 1

    while left <= right:
        mid = left + (right - left) // 2

        if nums[mid] == target:
            return mid

        # Determine which half is normally sorted
        if nums[left] <= nums[mid]:
            # Left half is sorted
            if nums[left] <= target < nums[mid]:
                right = mid - 1
            else:
                left = mid + 1
        else:
            # Right half is sorted
            if nums[mid] < target <= nums[right]:
                left = mid + 1
            else:
                right = mid - 1

    return -1
function search(nums: number[], target: number): number {
    // Time Complexity:  O(log n)
    // Space Complexity: O(1)
    let left = 0;
    let right = nums.length - 1;

    while (left <= right) {
        const mid = left + Math.floor((right - left) / 2);

        if (nums[mid] === target) return mid;

        // Check if left half is sorted
        if (nums[left] <= nums[mid]) {
            if (nums[left] <= target && target < nums[mid]) {
                right = mid - 1;
            } else {
                left = mid + 1;
            }
        } else {
            // Right half is sorted
            if (nums[mid] < target && target <= nums[right]) {
                left = mid + 1;
            } else {
                right = mid - 1;
            }
        }
    }

    return -1;
}
public class RotatedBinarySearch {
    /**
     * LeetCode 33 (Grind 75) in O(log n) time and O(1) space.
     */
    public static int search(int[] nums, int target) {
        int left = 0;
        int right = nums.length - 1;

        while (left <= right) {
            int mid = left + (right - left) / 2;

            if (nums[mid] == target) return mid;

            if (nums[left] <= nums[mid]) {
                // Left half is sorted
                if (nums[left] <= target && target < nums[mid]) {
                    right = mid - 1;
                } else {
                    left = mid + 1;
                }
            } else {
                // Right half is sorted
                if (nums[mid] < target && target <= nums[right]) {
                    left = mid + 1;
                } else {
                    right = mid - 1;
                }
            }
        }

        return -1;
    }
