Strings & Byte Representation

How text lives in memory, why string immutability causes hidden O(n²) bottlenecks, and how to manipulate characters at maximum speed.

In virtually every interview problem involving text—palindromes, anagrams, DNA sequences, parsing—candidates fail not because their algorithm is wrong, but because they unknowingly trigger hidden O(n) heap allocations during string concatenation or slicing.

💡

Tied to Your Interview Mission

In Python, TypeScript, and Java, strings are strictly immutable. Every single time you append a character with s += c, the runtime allocates a brand new character array and copies every single existing character over. A loop of n appends that looks linear is actually quadratic O(n²)!

1. Strings in Physical RAM: Characters vs. Bytes

At the hardware level, computers only store bits (0s and 1s). A string is conceptually an array of characters, but physically it is encoded into bytes:

  • ASCII: Each English character fits in exactly 1 byte (8 bits, 0–127).
  • UTF-8: Variable-width encoding (1 to 4 bytes per character). Common English text takes 1 byte; accented glyphs take 2; emoji and Asian scripts take 3 to 4 bytes.
  • UTF-16: Java and JavaScript historically use 16-bit code units (2 bytes each). Characters beyond the Basic Multilingual Plane (such as emojis) require 2 code units (surrogate pairs, 4 bytes).
Memory layout of ASCII string "DSA":
Address:    0x1000   0x1001   0x1002
Value:      0x44     0x53     0x41
Character:  'D'      'S'      'A'

Because strings are contiguous arrays under the hood, accessing an ASCII character at a known index is O(1). However, because languages protect string interning and thread safety, the underlying array is sealed and cannot be modified in place.

2. The Immutability Trap: Accidental O(n²) Concatenation

Consider this naive pattern: building a reversed string character-by-character: 

s = ""
for char in input_string:
    s = s + char  # DANGER: Allocates new string of length k and copies all k bytes!

On iteration 1, you copy 1 byte. On iteration 2, you copy 2 bytes. On iteration n, you copy n bytes. The total operations performed: 

1 + 2 + 3 + ... + n = (n * (n + 1)) / 2  ==>  O(n²) Time Complexity!

For a string of 100,000 characters, an O(n) approach takes 0.01 seconds; an O(n²) approach takes over 30 seconds and exhausts heap memory.

3. String Slicing & Substring Memory Copies

A frequent misconception is that taking a slice like s[i:j] or s.substring(i, j) is an O(1) pointer operation.

In modern Python, TypeScript, and Java (post-JDK 7u6), slicing a string creates a brand new string copy in the heap. If the substring has length k, slicing takes O(k) time and O(k) auxiliary space.

Interview Rule: When checking palindromes or scanning substrings, never slice strings repeatedly inside a loop. Pass integer pointer indices (left, right) instead!

4. Multi-Language Idiom Crosswalk

Here is how to properly construct strings in linear O(n) time across Python, TypeScript, and Java: 

# INCORRECT: O(n²) time due to repeated string copying
def slow_reverse(text: str) -> str:
    res = ""
    for ch in text:
        res = ch + res  # O(n²) trap!
    return res

# OPTIMAL 1: List append + join -> strictly O(n) time & O(n) space
def fast_builder(items: list[str]) -> str:
    chunks = []
    for item in items:
        chunks.append(item)  # O(1) amortized
    return "".join(chunks)   # Single O(n) pass memory allocation

# OPTIMAL 2: Two-pointer in-place reversal using mutable list
def reverse_chars(s: list[str]) -> None:
    left, right = 0, len(s) - 1
    while left < right:
        s[left], s[right] = s[right], s[left]  # O(1) swap
        left += 1
        right -= 1
// INCORRECT: O(n²) string allocation trap
function slowBuild(words: string[]): string {
    let result = "";
    for (const w of words) {
        result += w; // Allocates brand new string each iteration!
    }
    return result;
}

// OPTIMAL 1: Array push + join() -> strictly O(n) time
function fastBuild(words: string[]): string {
    const buffer: string[] = [];
    for (const w of words) {
        buffer.push(w); // O(1) amortized
    }
    return buffer.join(""); // Single O(n) contiguous allocation
}

// OPTIMAL 2: In-place two-pointer reversal on character array
function reverseString(s: string[]): void {
    let left = 0;
    let right = s.length - 1;
    while (left < right) {
        const temp = s[left];
        s[left] = s[right];
        s[right] = temp;
        left++;
        right--;
    }
}
// INCORRECT: Repeated string concatenation creates n objects in heap
public String slowBuild(String[] words) {
    String res = "";
    for (String w : words) {
        res += w; // O(n²) reallocations!
    }
    return res;
}

// OPTIMAL 1: StringBuilder with amortized capacity doubling -> strictly O(n)
public String fastBuild(String[] words) {
    StringBuilder sb = new StringBuilder();
    for (String w : words) {
        sb.append(w); // O(1) amortized char array copy
    }
    return sb.toString(); // Single O(n) string creation
}

// OPTIMAL 2: In-place two-pointer on char array
public void reverseString(char[] s) {
    int left = 0;
    int right = s.length - 1;
    while (left < right) {
        char temp = s[left];
        s[left] = s[right];
        s[right] = temp;
        left++;
        right--;
    }
}
