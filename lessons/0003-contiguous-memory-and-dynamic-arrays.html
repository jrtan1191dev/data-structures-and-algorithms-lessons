Contiguous Memory & Dynamic Arrays

Why index access is pure math, why shifting is expensive, and how dynamic arrays resize behind the scenes.

Nearly every complex data structure—strings, hash tables, heaps, graphs, matrix grids—is built directly on top of arrays. To write high-performance software and crack technical interviews, you must understand how arrays physically live in your computer's RAM.

💡

Tied to Your Interview Mission

In interview problems (like Two Pointers, Sliding Window, or Prefix Sums), interviewers will scrutinize whether you mutate arrays in-place or accidentally trigger hidden O(n) shifts (e.g. using nums.insert(0, x) or nums.shift()). This lesson ensures you avoid those traps instinctively.

1. The Physical Memory Layout

Think of your computer's RAM as an immense row of consecutively numbered mailboxes, each holding 1 byte of data. When you create an array, the operating system reserves a contiguous (unbroken) block of mailboxes.

Because the block is unbroken and each element takes up the exact same number of bytes (for example, 4 bytes for a 32-bit integer), the CPU never needs to "search" for an item by index. It computes the physical address using basic multiplication: 

TargetAddress = BaseAddress + (Index × ElementSizeInBytes)

If your array begins at memory address 1000 and stores 4-byte integers:

  • Index 0 lives at: 1000 + (0 × 4) = 1000
  • Index 1 lives at: 1000 + (1 × 4) = 1004
  • Index 1,000,000 lives at: 1000 + (1,000,000 × 4) = 4,001,000

Computing an offset takes a single CPU clock cycle. This is why array indexing arr[i] is strictly O(1) constant time.

2. The Inherent Cost: Insertion & Deletion

The rigid contiguous nature that gives arrays lightning-fast access also creates their biggest weakness: resizing and shifting.

  • Inserting at index 0 (Prepend): Every existing item must be copied one slot to the right to make room. For an array of length n, this requires n shifts → O(n) time.
  • Deleting at index 0: Removing the first item leaves a hole. Every remaining item must shift one slot to the left → O(n) time.
  • Appending at the end: If there is empty space at the end, zero shifts are required → O(1) time.

3. Dynamic Arrays & Amortized Analysis

In languages like Python (list), JavaScript/TypeScript (Array), and Java (ArrayList), arrays grow dynamically as you append items. How is that possible if RAM must be contiguous?

A dynamic array maintains an underlying fixed array and tracks two metrics:

  1. Length (Size): How many actual elements are stored.
  2. Capacity: How many memory slots are allocated in RAM.

When the array runs out of capacity (i.e., Length == Capacity):

  1. It allocates a new contiguous block in RAM with double the capacity (2×).
  2. It copies all n existing elements into the new block (an O(n) operation).
  3. It frees the old block and inserts the new item.
📈

Why is Append "Amortized O(1)"?

Yes, the doubling step takes O(n) time. But it happens so infrequently that the cost is spread out ("amortized") over thousands of previous cheap appends.

Doubling from capacity 1 to 2, 4, 8, 16... means after inserting n elements, the total number of copied items across all resizes never exceeds 2n. Dividing 2n by n operations gives an average cost of roughly 2 operations per append → O(1) amortized.

4. Multi-Language Idiom Crosswalk

# Python lists are dynamic arrays under the hood
nums = [10, 20, 30]

# O(1) Fast Operations:
nums.append(40)       # O(1) amortized append at end
val = nums[1]         # O(1) direct index access
nums.pop()            # O(1) remove from end

# O(n) Slow Operations:
nums.insert(0, 99)    # O(n) shifts entire array right!
nums.pop(0)           # O(n) shifts entire array left!
sub = nums[1:3]       # O(k) creates a brand new copy of slice!
// TypeScript / JS Arrays are dynamic arrays
const nums: number[] = [10, 20, 30];

// O(1) Fast Operations:
nums.push(40);        // O(1) amortized append
const val = nums[1];  // O(1) direct index access
nums.pop();           // O(1) remove from end

// O(n) Slow Operations:
nums.unshift(99);     // O(n) prepends and shifts all elements right!
nums.shift();         // O(n) removes head and shifts all elements left!
const sub = nums.slice(1, 3); // O(k) shallow copy of slice
import java.util.ArrayList;

public class ArrayDemo {
    public static void main(String[] args) {
        // Fixed primitive array: length cannot change
        int[] fixed = new int[3];
        fixed[0] = 10; // O(1) direct memory access

        // Dynamic ArrayList: resizes by 1.5x when full
        ArrayList<Integer> nums = new ArrayList<>();
        
        // O(1) Fast Operations:
        nums.add(10);          // O(1) amortized append
        int val = nums.get(0); // O(1) direct access
        nums.remove(nums.size() - 1); // O(1) remove from end

        // O(n) Slow Operations:
        nums.add(0, 99);       // O(n) shifts elements right
        nums.remove(0);        // O(n) shifts elements left
    }
}
