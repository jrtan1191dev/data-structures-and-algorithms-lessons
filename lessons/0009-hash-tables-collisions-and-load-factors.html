Hash Tables, Collisions & Load Factors

How hash functions convert arbitrary objects into array indices, how collision resolution prevents data loss, and why load factor doubling preserves O(1) average lookup.

The Hash Table (Python dict, TypeScript Map/Set, Java HashMap/HashSet) is the workhorse of technical interviews. It allows developers to trade $O(n)$ space for instantaneous $O(1)$ key lookup.

💡

Tied to Your Interview Mission

Senior interviewers love to probe: "You say lookup is O(1). When can it degrade to O(n)?" Answering with authority means explaining hash collisions, bad distribution, and worst-case bucket chain traversal, proving you understand production systems and not just LeetCode templates.

1. The Hash Function & Bucket Array Mechanics

Under the hood, a hash table is simply a contiguous array of buckets. When you insert a key-value pair map.put(key, value):

  1. The key is passed to a hash function which computes a large integer hash code: hash = hashCode(key).
  2. The hash code is compressed to a valid array index using the modulo operator: index = hash % capacity.
  3. The value is stored at bucket[index].
Key ("user_99") -> HashFunction() -> 84920412 -> % Capacity(16) -> Bucket Index [12]
Direct RAM access: BaseAddress + (12 * BucketSize) -> Instant O(1)

3. Collision Resolution: Separate Chaining vs. Open Addressing

Because possible keys are infinite while table capacity is finite, two distinct keys will inevitably produce the same bucket index (the Pigeonhole Principle).

  • Separate Chaining (Java HashMap): Each bucket points to a linked list of entries with the same index. In Java 8+, if a single bucket chain exceeds 8 entries, Java dynamically converts the linked list into a self-balancing Red-Black Tree, capping worst-case lookup at O(log n).
  • Open Addressing (Python dict): All entries reside directly within the array. If bucket[index] is occupied, the algorithm probes another slot (linear probing: index + 1, or quadratic probing) until an empty cell is found.

4. Load Factor & The Cost of Dynamic Resizing

The Load Factor ($\alpha$) measures how full the hash table is: 

Load Factor (α) = (Number of Stored Entries) / (Total Bucket Capacity)

Standard implementations (like Java's HashMap) set the default maximum load factor to 0.75. When $\alpha \ge 0.75$:

  1. The hash table allocates a new bucket array of $2\times$ capacity.
  2. Every single existing key must be rehashed to find its new bucket index in the doubled array.

Like dynamic arrays, this costly $O(n)$ resize happens exponentially less often, preserving O(1) amortized insertions.

5. Multi-Language Implementations: Two Sum

Solving LeetCode 1 (Grind 75) in optimal $O(n)$ time and $O(n)$ space across Python, TypeScript, and Java: 

def two_sum(nums: list[int], target: int) -> list[int]:
    """
    LeetCode 1 (Grind 75) - Single-pass Hash Map.
    Time Complexity:  O(n) - each lookup and insertion is O(1) average.
    Space Complexity: O(n) - stores up to n elements in hash map.
    """
    seen = {}  # maps value -> index

    for i, num in enumerate(nums):
        complement = target - num
        if complement in seen:
            return [seen[complement], i]
        seen[num] = i

    return []
function twoSum(nums: number[], target: number): number[] {
    // Time Complexity:  O(n) single pass
    // Space Complexity: O(n)
    const seen = new Map();

    for (let i = 0; i < nums.length; i++) {
        const num = nums[i];
        const complement = target - num;

        if (seen.has(complement)) {
            return [seen.get(complement)!, i];
        }
        seen.set(num, i);
    }

    return [];
}
import java.util.HashMap;

public class TwoSum {
    /**
     * LeetCode 1 (Grind 75) in O(n) time and O(n) space.
     */
    public static int[] twoSum(int[] nums, int target) {
        HashMap<Integer, Integer> seen = new HashMap<>();

        for (int i = 0; i < nums.length; i++) {
            int complement = target - nums[i];
            if (seen.containsKey(complement)) {
                return new int[] { seen.get(complement), i };
            }
            seen.put(nums[i], i);
        }

        return new int[0];
    }
}
